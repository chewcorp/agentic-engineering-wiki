# agentic-engineering-wiki

A curated, sourced wiki of agentic engineering knowledge, covering how to build
LLM agents and applications that work. It is packaged as a single
[Open Knowledge Format (OKF)](https://github.com/chewcorp/okf-core) bundle.
The same Markdown files serve as retrievable context for agents and as a
browsable docs site.

Every note is an atomic concept with a one-sentence description, inline links
to related concepts, and `sources:` frontmatter that traces it to the papers,
books and posts it was distilled from.

## Layout

```
wiki/                 the bundle: atomic concept notes
├── *.md              overview concepts and model fundamentals (start here)
├── prompting/        what text you write for a call
├── instructions/     standing instructions: AGENTS.md, skills, steering files
├── context/          what goes in the window, in what order, at what budget
├── knowledge/        retrieval, memory and knowledge bases outside the window
├── reasoning/        CoT, decomposition, search, voting, test-time compute
├── harness/          tools, agent-computer interfaces, observations, approvals
├── orchestration/    agent loops, planning, workflows, multi-agent
├── evaluation/       graders, eval suites, pass@k, ablations
├── optimization/     TextGrad, DSPy, harness evolution, self-adapting contexts
├── security/         prompt injection, guardrails, containment
└── development/      building software with agents: specs, ambiguity, patches
skills/agentic-wiki/  consumption skill (also exposed as .claude/skills)
docs/wiki-rules.md    authoring rules: atomicity, linking, placement
```

Each folder's `index.md` is generated by `okf index` from its
`_directory.yml` and the notes' frontmatter. Don't edit it by hand.

## Consuming it

**From an agent.** Load this repo as an
[Agent Plugins](https://github.com/agentplugins/agent-plugins-spec) plugin
(`plugin.json` + `skills/` + `wiki/` at the root). For example, run
`/plugin install` on a checkout in Claude Code. The `agentic-wiki` skill
routes a question to a folder, finds a seed note, and follows links one hop at
a time. It works with or without the `okf` CLI.

**With `okf`:**

```sh
pip install okf-core --index-url https://chewcorp.github.io/okf-core/simple/ \
  --extra-index-url https://pypi.org/simple/
okf search --bundle agentic-engineering "tool inventory size"
okf context --bundle agentic-engineering --seed harness/tool-inventory --budget-chars 12000
```

**As a site.** CI deploys the site to GitHub Pages on every push to `main`.
To build it locally:

```sh
pip install -r requirements-docs.txt
mkdocs serve
```

## Contributing notes

Read [`docs/wiki-rules.md`](docs/wiki-rules.md). In short:

- One concept per note, in the folder whose routing question it answers.
- Links stay inside `wiki/`.
- No hub notes.
- Run `okf index --bundle agentic-engineering --recurse` after you add or
  rename notes.

CI fails if the bundle doesn't validate, if any link is broken, if the
generated indexes are stale, or if the site build fails.

This repo holds curated notes only. Source ingest (fleeting notes, literature
notes) happens upstream and is not part of this repository.
